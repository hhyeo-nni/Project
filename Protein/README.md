# 프로틴 할인 알림

쿠팡 프로틴(단백질 보충제) 상품 페이지를 주기적으로 확인해서, 목표가 도달·할인율·최저가 갱신·재입고 같은 조건이 맞으면 **윈도우 우측 하단 토스트 알림**을 띄워주는 데스크톱 프로그램입니다.

- 백그라운드에서 트레이(작업표시줄 우측 하단)에 상주하며, 설정한 주기마다 등록된 상품들의 가격을 자동으로 확인합니다.
- 목표가/할인율/할인율급등/최저가갱신/재입고/단백질1g당단가, 6가지 규칙 중 원하는 것만 골라 상품별로 설정할 수 있습니다.
- 토스트는 **3줄**(상품명 / 핵심 알림 내용 / 정가·할인율·직전가 등 상세) + **"상품 열기" 버튼**으로 뜨며, 본문을 클릭하거나 버튼을 누르면 바로 해당 쿠팡 상품 페이지가 열립니다.
- 쿠팡의 Akamai 봇 차단을 우회하기 위해 SeleniumBase UC 모드로 실제 크롬 브라우저를 조작합니다. 영구 프로필은 쓰지 않고, 확인할 때마다 깨끗한 임시 프로필로 새로 시작합니다.

## 빠른 시작

### 1. 설치된 패키지 확인

이 프로젝트는 가상환경 없이 시스템 Python(`python --version` → 3.14)을 그대로 사용합니다. 아래 명령으로 필요한 패키지가 설치되어 있는지 확인하세요.

```bat
pip show selenium seleniumbase winotify pystray Pillow sv_ttk
```

(`winotify`는 실제 알림 표시에는 쓰이지 않고 진단 도구 `tools\알림테스트.py` 전용입니다. 자세한 내용은 아래 "알림이 전혀 안 떠요" 항목을 보세요.)

빠진 패키지가 있다면:

```bat
pip install -r requirements.txt
```

Chrome 브라우저(데스크톱용 정식 크롬)가 설치되어 있어야 합니다. SeleniumBase(UC 모드)가 설치된 크롬 버전에 맞는 드라이버를 자동으로 관리합니다.

### 2. 실행

- 평소 사용: **`실행.bat`** 더블클릭 → 콘솔 창 없이 트레이에만 아이콘이 뜹니다.
- 문제 확인/디버그용: **`디버그실행.bat`** 더블클릭 → 검은 콘솔 창에 로그가 실시간으로 찍힙니다. 문제가 생기면 이 창의 로그를 먼저 확인하세요.
- 콘솔에서 직접: `python main.py` (프로젝트 루트에서)

처음 실행하면 `config.json`이 기본값으로 자동 생성됩니다. 매 확인 사이클마다 브라우저가 새 임시 프로필로 뜨고, 쿠팡 홈 → 검색 → 상품 순서로 신뢰 세션을 만드는 과정(워밍업)을 거치므로 상품 1개당 확인에 다소 시간이 걸릴 수 있습니다(정상입니다).

같은 프로그램을 두 번 실행하면(윈도우 뮤텍스로 감지) 안내 토스트만 뜨고 새 인스턴스는 조용히 종료됩니다.

### 3. 상품 등록하는 법

1. 쿠팡 앱/웹에서 감시하고 싶은 프로틴 상품 페이지로 들어가서 **주소창의 URL을 복사**합니다. (예: `https://www.coupang.com/vp/products/9684343895?itemId=...&vendorItemId=...`)
2. 트레이 아이콘을 **우클릭 → "⚙ 설정 / 상품 관리"**를 클릭합니다.
3. 설정 창에서 **"상품 추가"** 버튼 클릭 → URL 붙여넣기 → **"상품 조회"**를 누르면 브라우저가 잠깐 상품 페이지를 열어 상품명을 자동으로 채워줍니다(느릴 수 있습니다. 실패하면 상품명을 직접 입력해도 됩니다).
4. 단백질 1g당 단가 규칙을 쓰려면 상품의 "총 단백질 g"(예: 1kg 제품에 단백질 함량 75%면 750g)을 입력합니다. 선택 사항입니다.
5. "추가"를 누르면 바로 규칙 편집 창이 이어서 열립니다 — 원하는 알림 규칙에 체크하고 값을 입력한 뒤 "저장"하면 즉시 다음 확인 사이클부터 반영됩니다.

## 알림 규칙 6종

각 상품마다 원하는 규칙만 켜서 조합할 수 있습니다. 모든 규칙은 공통으로 **쿨다운**(기본 12시간, 같은 규칙이 반복해서 알림 보내는 것을 억제)이 적용되며, "더 싸지면 재알림" 옵션이 켜져 있으면 쿨다운 중이라도 직전 알림 때보다 가격이 더 내려가면 다시 알립니다.

| 규칙 | 언제 울리나 | 넣는 값 | 예시 |
|---|---|---|---|
| **목표가 이하** (`target_price`) | 실구매가가 설정한 목표가 **이하**로 떨어졌을 때 | 원(₩) | 목표가 `45000` 입력 → 45,900원이던 상품이 41,900원이 되면 알림 |
| **할인율 N% 이상** (`discount_rate`) | 화면에 표시된 할인율이 설정값 **이상**일 때 | % (정수) | `30` 입력 → 할인율이 30% 이상으로 표시되면 알림 |
| **할인율 급등** (`discount_spike`) | 최근 7일 평균 할인율보다 오늘 할인율이 설정값(%p) 이상 급등했을 때 | %p(퍼센트포인트) | `15` 입력 → 최근 평균 20%였는데 오늘 40%로 뛰면(+20%p ≥ 15) 알림 |
| **최저가 갱신** (`lowest_ever`) | 지금까지 기록된 전체 기간 최저가보다 더 낮은 가격이 나왔을 때 | 값 불필요(0) | 이전 최저 42,000원 → 오늘 39,900원이면 알림 |
| **재입고** (`restock`) | 직전 확인 때 품절이었다가 이번에 재고 있음으로 바뀌었을 때 | 값 불필요(0) | 품절 표시가 사라지고 구매 가능해지면 알림 |
| **단백질 1g당 단가 이하** (`unit_price`) | (실구매가 ÷ 등록한 총 단백질 g)이 설정값 **이하**일 때 | 원/g | 단백질 800g 상품이 36,700원이면 g당 45.9원 → 기준을 `50`으로 두면 알림 |

품절 상태(`out_of_stock`)일 때는 재입고 규칙만 판정되고 나머지 5종은 자동으로 건너뜁니다. 가격을 못 읽었을 때(파싱 실패, `price = None`)는 어떤 알림도 울리지 않습니다.

## 바탕화면 · 시작 메뉴에 등록하기

윈도우 **시작 메뉴 검색은 시작 메뉴 폴더의 `.lnk` 파일을 색인**합니다. 그래서 프로그램을 따로 "설치"하지 않아도 바로가기만 만들어 두면 시작 버튼에서 검색됩니다.

```
python tools\바로가기_만들기.py            # 바탕화면 + 시작 메뉴에 만들기
python tools\바로가기_만들기.py --자동시작  # 위 + 윈도우 켤 때 자동 실행까지
python tools\바로가기_만들기.py --상태      # 지금 어디에 등록돼 있는지 확인
python tools\바로가기_만들기.py --제거      # 세 곳 모두에서 제거
```

만들어진 바로가기는 `pythonw.exe`로 `main.py`를 실행하며(콘솔 창 없음), 아이콘은 `ui/icon.ico`가 지정됩니다.

> **알아두세요**
> - 바로가기는 **절대 경로**를 담고 있습니다. 프로젝트 폴더를 옮기거나 이름을 바꾸면 바로가기가 깨지니, 그때는 도구를 다시 실행해 새로 만드세요.
> - 폴더 위치는 윈도우 특수 폴더 API로 얻습니다. 바탕화면이 다른 드라이브로 옮겨져 있어도(회사 PC에서 흔합니다) 정확한 위치에 만들어집니다.
> - `설정 → 앱` 목록(제거 프로그램)에는 나타나지 않습니다. 그건 설치 프로그램을 따로 만들어야 하는 별개 작업입니다.

## 화면 테마 · 글꼴 설정

설정 창(트레이 → "⚙ 설정 / 상품 관리")은 [`sv-ttk`](https://pypi.org/project/sv-ttk/) 2.6.1을 적용해 Windows 11 스타일로 표시됩니다. 창 아래쪽 "전역 설정" 영역에서:

- **화면 테마**: 라이트 / 다크 라디오 버튼. 고르는 즉시 창 전체에 반영됩니다(창을 새로 열 필요 없음).
- **글꼴**: 이름 + 크기(9~13) 콤보박스. 기본값은 **Noto Sans KR**(구글이 만든 현대적인 한글 글꼴)이며, 이 PC에 실제로 설치된 것만 목록에 나옵니다. 후보: `Noto Sans KR`, `맑은 고딕`, `맑은 고딕 Semilight`, `함초롬돋움`, `돋움`.

> **왜 한글 글꼴만 고를 수 있나요?**
> `Segoe UI` / `Segoe UI Variable` 같은 글꼴에는 **한글 글자가 들어있지 않습니다.** 이런 글꼴을 고르면 영문·숫자만 그 글꼴로 나오고 **한글만 굴림으로 대체**되어 화면이 뒤죽박죽이 됩니다(실제로 이 증상이 보고됐습니다). 그래서 목록에는 한글이 있는 글꼴만 넣었고, 설정 파일에 그런 글꼴이 남아 있어도 자동으로 대체합니다.

> **sv-ttk 테마와 글꼴의 관계 (중요)**
> `sv-ttk`는 `SunValleyBodyFont` 같은 **자체 글꼴을 만들어 위젯 스타일에 직접 지정**하는데, 그 기본값이 한글이 없는 `Segoe UI Variable` 계열입니다. 그래서 Tk 표준 글꼴만 바꾸면 제목만 바뀌고 **표·버튼·체크박스는 굴림으로 남습니다.** 이 프로그램은 테마를 입힌 뒤 `SunValley*` 글꼴 8종과 주요 ttk 스타일까지 전부 덮어쓰며, **테마를 전환할 때마다 다시 덮어씁니다**(테마를 다시 적용하면 sv-ttk가 자기 글꼴로 되돌리기 때문).

둘 다 고르는 즉시 `config.json`에 저장됩니다(창 하단의 전역 "저장" 버튼과는 무관하게, 선택하는 순간 바로 기록됩니다).

알려진 제약: `tkinter.messagebox`로 뜨는 오류/확인 팝업은 OS 네이티브 창이라 테마가 적용되지 않고 항상 윈도우 기본 스타일로 뜹니다.

`sv-ttk`가 설치되어 있지 않으면 오류 없이 기본 tkinter 테마로 창이 뜹니다(테마/글꼴 선택 자체는 여전히 동작).

## 쿠팡 차단(Akamai) 관련 주의사항

쿠팡은 Akamai Bot Manager로 보호됩니다. 기존에는 `undetected-chromedriver`로 수집했지만 더 이상 동작하지 않아 **수집 방식을 전면 교체**했습니다. `core/scraper.py`의 모듈 docstring에 남겨진 2026-09-03 실측 결과는 다음과 같습니다.

| 방식 | 결과 |
|---|---|
| `requests` + 완전한 브라우저 헤더 | ❌ 403 (모바일 도메인 루트까지 전부 차단) |
| 모바일 사이트(m.coupang.com) / 내부 JSON API 추정 경로 | ❌ 403 |
| Selenium 헤드리스 | ❌ 403 |
| Selenium 일반 창 (Chrome / Edge) | ❌ `_abck` 쿠키가 봇 판정 |
| undetected-chromedriver 3.5.5 | ❌ Chrome 151에서 더는 못 피함 |
| nodriver 0.50.3 | ❌ 챌린지 단계까지만 도달 |
| 자동화 플래그 없는 순정 브라우저에 나중에 CDP 접속 | △ 홈·검색은 통과, 상품에서 차단 |
| **SeleniumBase UC 모드** | ✅ **통과** |

### 왜 SeleniumBase UC 모드만 통과하는가

`uc_open_with_reconnect(url, reconnect_time)`은 페이지를 여는 동안 자동화 연결(CDP)을 **아예 끊었다가**, 로딩이 끝난 뒤 다시 붙습니다. Akamai의 행동분석 센서가 도는 바로 그 순간에 자동화 흔적이 없어서 봇으로 판정되지 않습니다.

반대로 일반 Selenium은 CDP가 계속 붙어 있어서 센서에 잡히고, 그 결과 Akamai의 `_abck` 쿠키가 봇 판정(`~-1~`) 상태로 굳습니다. 이 상태가 되면 홈페이지는 열려도 `/np/search`, `/vp/products` 같은 보호 경로는 403이 납니다. 실제로 `_abck` 값을 직접 확인해 이 진단을 확정했습니다.

이 실측 결과 때문에 지켜야 할 것들이 있습니다.

- **헤드리스 모드는 절대 쓰지 않습니다.** 설정 창의 "확인할 때 브라우저 창 숨기기"를 체크하면(기본값 켜짐), 진짜 헤드리스 대신 브라우저를 **화면 밖 좌표(`-32000,-32000`)에서 띄웁니다.** 이 좌표는 윈도우가 최소화된 창을 보관하는 위치라 절대 보이지 않습니다. 핵심은 창을 띄운 *뒤에* 옮기는 게 아니라 **기동 인자로 위치를 넘긴다**는 점입니다 — 나중에 옮기면 창이 잠깐 화면에 번쩍이면서 작업 중인 창 위로 튀어나옵니다. 화면 밖 배치 상태에서도 쿠팡을 정상 통과하는 것을 실측 확인했습니다.
- **상품 URL로 바로 들어가면 실패합니다.** 반드시 홈 → 검색 → 상품 순서로 자연스럽게 이동해야 통과합니다(UC 모드에서도 직접 진입은 실패). 그래서 매 확인 사이클마다 브라우저가 먼저 쿠팡 홈과 검색 결과를 거쳐 워밍업한 뒤 등록된 상품들을 순회합니다.
- **영구 브라우저 프로필을 쓰지 않습니다.** 확인할 때마다 완전히 깨끗한 임시 프로필로 새 브라우저를 띄웁니다. 한 번 봇으로 찍힌 프로필은 `_abck`가 오염된 채 굳어버리기 때문에, 오히려 프로필을 재사용하지 않는 쪽이 안정적입니다. 별도로 관리하거나 보존해야 할 프로필 폴더는 없습니다.
- **확인 주기를 너무 짧게(30분 미만) 잡지 마세요.** 짧은 시간에 접속을 많이 하면 세션 신뢰도가 깎여 차단당하기 쉽습니다. 기본값(30분)이나 그 이상을 권장합니다.
- **차단당했을 때(워밍업 실패·403)의 동작**: `core/scraper.py`의 `fetch()`/`probe()`는 첫 시도에서 페이지가 준비되지 않으면(`access_denied`/`coupang_403`/`too_short`) 자동으로 홈 → 검색 워밍업을 한 번 더 태우고 1회 재시도합니다. 그래도 실패하면 예외를 던지지 않고 `price=None`(또는 빈 상품 정보)을 반환하며, 다음 정기 확인 사이클에서 새 임시 프로필로 다시 시도합니다. 즉 대부분의 차단은 별도 조치 없이 다음 사이클에서 자연히 회복됩니다.
- **그래도 계속 막히면**:
  1. 설정 창에서 확인 주기를 60분 이상으로 늘립니다.
  2. `data\logs\app.log`에서 `page_not_ready`, `access_denied`, `coupang_403` 같은 문구가 반복되는지 확인합니다.
  3. 몇 시간(2~3시간 권장) 기다립니다. Akamai 차단은 시간이 지나면 대개 풀립니다.
  4. 그래도 안 되면 공유기를 재시작해 공인 IP를 바꿔보는 것도 방법입니다.

## 문제 해결 (FAQ)

**Q. 알림이 전혀 안 떠요.**
- `data\logs\app.log`를 열어 최근 로그를 확인하세요(트레이 → "📂 로그 폴더 열기").
- 상품의 규칙이 실제로 켜져 있는지(설정 창에서 편집 → 체크박스) 확인하세요.
- 최근에 같은 규칙으로 이미 알림을 보냈다면 **쿨다운**(기본 12시간) 때문에 억제된 것일 수 있습니다. "더 싸지면 재알림"이 켜져 있으면 그 사이에 더 싸질 때만 다시 울립니다.
- **로그에 `토스트 알림 실패(rc=...)` 가 찍혀 있다면** 그 로그 줄에 실패 원인(PowerShell stderr)이 그대로 남아 있습니다. 가장 흔한 원인은 윈도우 앱 등록(AUMID) 문제입니다.
  - 이 프로그램은 실행할 때 `HKCU\SOFTWARE\Classes\AppUserModelId\프로틴 할인 알림` 에 앱을 **자동 등록**합니다(관리자 권한 불필요).
  - 실제로 윈도우까지 전달됐는지는 PowerShell로 확인할 수 있습니다:
    `Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Notifications\Settings\프로틴 할인 알림'`
    → `PeriodicNotificationCount` 가 올라가면 OS까지 도달한 것입니다.
  - `python tools\알림테스트.py` 를 실행하면 방식이 다른 토스트 4종을 띄워 어디서 막히는지 짚어줍니다.
  - 그래도 안 되면 `config.json`의 `notify_app_id` 에 이미 등록된 다른 앱 식별자를 지정해 우회할 수 있습니다.
- **로그에 `토스트 알림 표시:` 가 찍혀서 PowerShell 호출까지는 성공했는데도 화면에 배너로 안 뜨고 알림 센터(작업표시줄 시계 클릭)에만 쌓여 있다면**, 윈도우 알림 자체가 막혀 있는 경우입니다.
  - 윈도우 **집중 지원(방해 금지)** 모드가 켜져 있지 않은지 확인하세요(작업표시줄 시계 근처 알림 아이콘 클릭 → 맨 아래 "집중 지원"이 "끄기"인지 확인).
  - `start ms-settings:notifications` 명령으로 윈도우 알림 설정을 열어, 이 프로그램(`프로틴 할인 알림`)의 알림이 켜져 있고 "배너 표시"가 허용돼 있는지 확인하세요.

**Q. 가격이 계속 `None`으로 나와요.**
- 십중팔구 Akamai 차단입니다. 로그에서 `page_not_ready:access_denied`, `page_not_ready:coupang_403`, `page_not_ready:too_short`, `browser_start_failed` 같은 문구를 찾아보세요. `fetch()`는 차단을 감지하면 워밍업을 다시 태우고 자동으로 1회 재시도하므로, 한두 번의 차단은 보통 같은 사이클 안에서 스스로 복구됩니다. 반복된다면 위 "쿠팡 차단(Akamai) 관련 주의사항"을 따르세요(확인 주기를 30분 이상으로 유지, 60분 이상으로 늘려보기, 몇 시간 기다리기).
- `no_price_container`가 로그에 보이면 품절이거나(설정 창 → 해당 상품 → "가격 이력"에서 재고 상태 확인), 쿠팡이 화면 구조를 바꿨을 가능성이 있습니다. 아래 항목을 보세요.
- 로그에 `no_price_container+soldout`이 찍혀 있다면 그건 오류가 아니라 **정상적으로 품절을 감지한 것**입니다(아래 "품절이면 가격이 안 잡혀요" 항목 참고). `+soldout`이 없는 `no_price_container`만 반복된다면 쿠팡이 화면 구조를 바꿨을 가능성이 있으니 `selectors.json`을 확인하세요.

**Q. 품절이면 가격이 안 잡혀요. 오류인가요?**
- 정상입니다. 쿠팡은 상품이 품절이면 가격이 표시되는 `.price-container` 자체를 렌더링하지 않고, 대신 `품절` 문구가 담긴 요소(예: `prod-not-find-known__buy__info__txt`)만 보여줍니다. 그래서 품절 중에는 `price = None`이 정상 결과이고, 어떤 규칙도 울리지 않습니다(재입고 제외).
- 품절이었다가 다시 팔기 시작하면 알려받고 싶다면 해당 상품의 **재입고**(`restock`) 규칙을 켜 두세요. 다음 확인 사이클에서 재고 있음으로 바뀌는 순간 알림이 옵니다.
- 품절 감지는 파싱 실패로 세지 않습니다(`core/scheduler.py`의 `_track_fetch_result()`가 `availability == out_of_stock`이면 연속 실패 카운터를 초기화하고 "가격 파싱 실패" 오류 알림도 보내지 않습니다). 품절 상품을 등록해 뒀다고 오류 알림이 쌓이지는 않습니다.

**Q. 쿠팡이 화면을 개편해서 파싱이 깨진 것 같아요.**
- `selectors.json`만 고치면 됩니다. 다른 코드는 건드릴 필요가 없습니다.
- `price_container` 값을 실제 상품 페이지에서 가격이 표시되는 컨테이너의 CSS 선택자로 바꿔보세요.
- 가격 자체는 클래스명이 아니라 "폰트 크기 + 취소선 여부"라는 시각적 규칙으로 판별하므로(`core/parser.py` 참고), 쿠팡이 클래스명만 바꾸는 정도로는 대개 영향이 없습니다. 레이아웃 구조 자체가 바뀌었을 때만 `selectors.json` 수정이 필요합니다.

**Q. 브라우저 창이 뜨는 게 거슬려요.**
- 기본값으로 이미 숨겨져 있습니다. 혹시 창이 보인다면 설정 창(트레이 → 설정/상품 관리)에서 "확인할 때 브라우저 창 숨기기"가 체크돼 있는지 확인하세요. 창이 화면 밖(`-32000,-32000`)에서 뜨기 때문에 작업 중인 화면 위로 튀어나오지 않습니다. 진짜 헤드리스가 아니라 위치만 화면 밖일 뿐이라 차단 위험은 늘지 않습니다.
- **작업표시줄에도 뜨지 않습니다.** 화면 밖에 띄우는 것만으로는 작업표시줄 버튼까지 없어지지 않고, 게다가 SeleniumBase UC 모드가 페이지를 열 때마다 자동화 연결을 끊었다 다시 붙이면서 창을 다시 표시해 작업표시줄 버튼이 깜빡이는 문제가 있었습니다. `core/winhide.py`의 `TaskbarHider`가 브라우저를 띄우기 **전에** 감시 스레드를 시작해(50ms 간격 폴링) 수집용 크롬 창이 생기는 즉시 `WS_EX_TOOLWINDOW` 확장 스타일을 입혀 작업표시줄에서 완전히 숨깁니다. 이 스타일은 한 번 붙이면 페이지 이동으로 창이 다시 보이더라도 계속 유지됩니다(실측상 작업표시줄에 버튼이 노출되는 시간은 최대 50ms 남짓). 사용자가 원래 쓰던 크롬 창은 감시 시작 시점에 이미 열려 있던 창으로 기억해 두고 건드리지 않습니다. 이 동작도 "확인할 때 브라우저 창 숨기기" 옵션(기본 켜짐)에 같이 딸려 있어 별도 설정이 필요 없습니다.

## 설정 파일(config.json) 항목 설명

`config.json`은 최초 실행 시 자동 생성되며, 설정 창의 "전역 설정" 영역에서 수정하고 저장하면 이 파일에 반영됩니다. 상품 목록은 `products` 배열 안에 각각의 `rules`와 함께 저장됩니다.

| 필드 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `poll_interval_minutes` | 정수(분) | 30 | 가격 확인 주기 |
| `jitter_minutes` | 정수(분) | 5 | 주기에 더해지는 무작위 편차(±). 매번 정확히 같은 간격으로만 접속하면 봇으로 의심받기 쉬워 흔들어줌 |
| `cooldown_hours` | 정수(시간) | 12 | 같은 상품·같은 규칙의 재알림을 억제하는 최소 간격 |
| `renotify_on_lower` | true/false | true | 쿨다운 중이라도 직전 알림 가격보다 더 싸지면 다시 알림 |
| `sound` | true/false | false | 토스트 알림음 재생 여부 |
| `request_delay_seconds` | `[최소, 최대]`(초) | `[5, 15]` | 한 사이클 안에서 상품과 상품 사이에 두는 랜덤 대기 시간(첫 상품은 대기 없음) |
| `headless` | true/false | **true** | 확인할 때 브라우저 창을 화면 밖에서 띄울지 여부(진짜 헤드리스 아님, 위 주의사항 참고) |
| `notify_app_id` | 문자열/null | null | 토스트가 안 뜰 때 쓸 대체 앱 식별자(AUMID). 보통 건드릴 필요 없음 |
| `theme` | 문자열 | "light" | 설정 창 UI 테마. `"light"` 또는 `"dark"` (sv-ttk). 설정 창에서 라디오 버튼으로 선택하면 즉시 저장됨 |
| `font_family` | 문자열 | "Noto Sans KR" | 설정 창 UI 글꼴 이름. 한글이 없는 글꼴(Segoe UI 등)을 넣으면 자동으로 대체됨 |
| `font_size` | 정수 | 10 | 설정 창 UI 글꼴 크기(9~13). 설정 창 콤보박스에서 선택하면 즉시 저장됨 |
| `products` | 배열 | `[]` | 감시 상품 목록. 각 항목은 `product_id`, `url`, `name`, `protein_grams`, `enabled`, `rules`(`kind`/`threshold`/`enabled`) 등을 가짐 |
